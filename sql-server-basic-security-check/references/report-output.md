# レポートファイルの生成

スキルでチェックを実行したら、成功・一部失敗・接続失敗を含め、その実行結果をレポートファイルに保存する。ユーザーが保存不要と指定した場合は従う。これはスキルを使うエージェントの作業手順であり、PowerShell 実行スクリプト単体にファイル生成機能を追加するものではない。

## 形式と保存先

- ユーザーが指定した形式・保存先を優先する。指定がなければ UTF-8 の HTML を使い、作業ディレクトリの `reports/sql-server-security-YYYYMMDD-HHmmss.html` に保存する。ファイル名はレポート生成時刻を使い、同名なら連番を付けて既存ファイルを上書きしない。
- 保存先は実行開始時に絶対パスで確定する。インストール済みスキルのキャッシュ内へ保存しない。書き込み可能な作業ディレクトリが不明な場合のみ保存先を尋ねる。
- HTML は既定形式とし、UTF-8 の自己完結した `.html` とし、外部スクリプト・外部リソースを読み込まない。取得した名前やログを HTML エスケープしてテキストとして表示する。Markdown の表の区切り文字やコードフェンスも、取得文字列が構文として解釈されないように扱う。
- プレビューのみの場合は実行済みの診断レポートを生成しない。プレビューの保存を依頼された場合は、タイトルと各項目に「プレビューのみ・未判定」を明記する。

## 目次

レポートのタイトル直後、実行情報より前に「目次」を配置する。実行情報、結果サマリー、選択された全チェックの詳細節、未確認事項・エラー、変更の有無、検証等の実際に存在する主要節へ移動できるリンクを列挙する。存在しない節や未選択項目へのリンクは作らない。

Markdown は見出し直前に一意の明示アンカー（例: `<a id="check-01"></a>`）を置き、目次から `(#check-01)` で参照する。HTML は各見出しの id を参照する。目次自体を目次に含めず、保存後にリンク先の存在・一意性・全詳細節の掲載を確認する。

## 必須の構成

1. **実行情報**: 「項目」「値」の2列の Markdown／HTML 表で出力し、箇条書きやコードブロックだけで代用しない。実行開始・終了日時とタイムゾーン、指定した接続先・DB、取得できたサーバー名、認証方式、実行状況、選択項目。取得不能な情報は未取得とする。サーバーのログ日時や対象期間のタイムゾーンを推測しない。
2. **結果サマリー**: 項目、実行状況、判定、取得値または件数、判定根拠、未確認事項。各定義の「正常」「要確認」「情報」「検出あり／なし」「未判定」等を保持し、検出ありを異常、検出なしを正常へ置き換えない。対象外の項目は未選択と区別する。
3. **項目別の詳細**: 各節の冒頭に「チェックの目的」として実施理由を記載する。使用した SQL のファイル名、対象範囲・期間、取得値・全対象行と判定根拠を記載する。「使用SQL」と「判定」は別々の行に表示する。HTML は両者の間に br 要素を入れ、Markdown は半角スペース2つと改行を使う。同じ行に連結しない。Configuration option ログ、暗号化接続用証明書ログ（分類付き）、サービスアカウントの補助ログは日時・プロセス・本文全文をコードブロック（HTML では pre）で掲載する。TRUSTWORTHY、変更オブジェクト、変更ジョブ、sysadmin メンバー、リンクサーバー設定とログインマッピング、サービスアカウント（稼働状態・起動方式・最終起動日時）、DAC 接続、DAC 追跡の XE 定義（述語・稼働状態・記録先）も全対象行を載せ、msdb の既定値やグループ内ユーザー未確認等の注記を保持する。
4. **未確認事項・エラー**: 権限不足、非表示の DB・ログイン、取得失敗、途中停止、未実行の項目と理由。エラー前の結果を取得できなかった場合も推測で埋めず、取得できなかった旨を記す。
5. **変更の有無**: 実際に行った操作に基づき、設定・権限・ジョブの変更を行っていないことを記載する。

## 全チェックの掲載義務

- 実行前に一括入口の実装済みカタログと選択項目を照合し、レポートの項目一覧を作る。全項目実行では実装済みの全項目を掲載する。個別指定では選択項目を掲載し、未選択項目は対象範囲で明示する。未選択項目を追加実行しない。
- 選択された各チェックに、必ずサマリーの1行と詳細の節を設ける。検出0件、取得失敗、権限不足、前提不足、途中停止による未実行でも節を削除しない。件数0と未取得を区別し、未実行・未取得は未判定と理由を記載する。
- 複数の結果セットがあるチェックはすべて掲載する。サービスの DMV と補助ログ、リンクサーバーとマッピング、ログの分類別集計と全文等を一方だけにしない。

## 各チェックの目的（レポート必須）

各詳細節の冒頭に「チェックの目的」を設ける。ラベルは `**チェックの目的**:` の独立した行とし、その後に空行を1行入れて説明文を次の段落に記載する。同じ行に説明文を続けない。説明文は句点「。」ごとに改行する。Markdown では文末に半角スペース2つを付けて改行し、HTML では br 要素を使い、表示上も改行されるようにする。何を把握し、何の確認に役立てるかを次の説明に沿って記載する。実際の取得値・判定根拠とは区別し、0件・未実行・取得失敗でも目的を省略しない。目的の説明を根拠に新たな診断や判定基準を追加しない。

| Checks の識別子 | チェックの目的 |
| --- | --- |
| `xp_cmdshell` | SQL Server から OS コマンドを実行できる機能の有効状態を把握し、不要な機能が有効になっていないか確認するためです。有効でも実際の悪用を示すものではありません。 |
| `Ole Automation Procedures` | SQL Server から OLE Automation オブジェクトを利用する機能の有効状態を確認し、その利用の必要性を見直す材料を得るためです。機能自体の実行や利用履歴の調査は行いません。 |
| `clr enabled` | SQL Server 内でユーザー CLR コードを実行する機能の有効状態を確認し、利用の必要性を確認するためです。有効という値だけでアセンブリの危険性を判断しません。 |
| `Configuration option log` | サーバー設定の変更に関する記録を確認し、運用上の変更内容を照合する材料を得るためです。ログの存在だけでは不正な変更と判断できず、現在の設定値は別途確認します。 |
| `sa login` | 組み込みの管理者ログインが有効かを確認し、その利用の必要性を見直すためです。無効でも他の管理者ログインの安全性や権限管理全体を保証しません。 |
| `trustworthy` | データベースの信頼設定が有効な対象を把握し、データベース境界を越える権限利用の必要性を確認する材料を得るためです。msdb の ON は既定値として情報を注記し、有効だけで権限昇格の成立を断定しません。 |
| `recent object changes` | 直近のオブジェクト変更を一覧化し、予定された作業や変更管理の記録と照合するためです。最終変更日時に基づく一覧であり、変更者・変更内容や全変更履歴を証明するものではありません。 |
| `recent agent job changes` | 自動実行処理である SQL Server Agent ジョブの最近の変更を把握し、予定された運用変更と照合するためです。最終変更日時のみを確認し、変更の有無を正常・異常とは判定しません。 |
| `sysadmin logins` | インスタンスを管理できる強い権限を持つログインと付与経路を把握し、権限付与の必要性を確認する材料を得るためです。グループ内ユーザーや sysadmin 以外の個別権限はこのチェックでは確認しません。 |
| `DAC connections` | 管理用の接続が現在使用されているかを把握し、実施中の管理作業と照合するためです。観測時点の接続のみを確認し、過去の接続や不正使用の有無は判断しません。 |
| `DAC XE tracking` | DAC を含むログインを記録する拡張イベントの定義・稼働状態・記録先を把握し、管理用接続を追跡できる設定か確認するためです。設定の存在だけでは実際の記録成功や保存期間を保証しません。 |
| `service accounts` | SQL Server 関連サービスがどのアカウントで稼働しているか把握し、運用方針や権限管理を確認する材料を得るためです。DMV を現在の主結果とし、起動ログは補助情報として扱い、アカウントの適否を独自判定しません。 |
| `linked servers` | 外部データソースへの接続設定とログインマッピングを把握し、接続先と使用する認証コンテキストの必要性を確認するためです。ローカル設定のみを参照し、リンク先への接続可否や設定の適否は判定しません。 |
| `encryption certificate log` | 暗号化接続用の証明書について起動時の読み込み結果を確認し、失敗や自動生成証明書の使用を把握する材料を得るためです。読み込み成功だけでは現在の有効期限・信頼性・全接続の暗号化を保証しません。 |

## チェック追加時の必須更新

チェックを追加・変更する際は、SQL と実行カタログだけで完了としない。SKILL.md の項目一覧、チェック定義の報告内容、この掲載表、関連する実行手順を同じ変更で更新する。目的の説明表も更新し、定義には実施理由、取得値、判定、根拠、全詳細行、未確認事項、0件・失敗時の表示方法を指定する。

保存前後に、選択項目の集合とサマリー・詳細節の識別子を照合する。欠けた項目は理由付きの未判定として補い、対象項目数・全結果セット・詳細件数の一致を確認する。14項目などの固定件数だけで掲載完了と判断しない。

## オブジェクト変更の表示形式

一時オブジェクトは対象外とする。tempdb で名前が # で始まるオブジェクト（ローカル・グローバル一時テーブル、一時プロシージャ、表変数等）と、parent_object_id がそのオブジェクトを指す子オブジェクト（制約等）を SQL で除外する。tempdb 全体や他 DB の恒久オブジェクトを除外しない。DB 別件数・サマリー・一覧はすべて除外後の値で一致させ、除外後0件の取得成功 DB は既存ルールに従って省略する。

DB ごとの取得状況表では、取得成功かつ検出件数が0件の DB 行を省略する。1件以上の DB と、取得失敗・未確認（部分取得を含む）の DB は件数にかかわらず掲載する。全 DB のチェックは継続し、対象 DB 数・掲載 DB 数・0件で省略した DB 数を明記する。全 DB が取得成功で0件なら個別 DB 行は掲載せず「検出なし（0件）」と省略 DB 数を示す。変更オブジェクトの行は省略しない。

`recent object changes` の詳細は [チェック定義の表形式ルール](recent-object-changes.md#表形式での出力必須) に従い、DB ごとの取得状況と変更オブジェクト全行を見出し付きの表として掲載する。Markdown テーブルまたは HTML の table を使い、sqlcmd 原文のコードブロックだけで済ませない。保存後に表の列・行数・取得値の一致を確認する。

## リンクサーバー・ジョブの表示形式

[リンクサーバー設定](linked-servers.md#表形式での出力必須) と [変更ジョブ一覧](recent-agent-job-changes.md#表形式での出力必須) は、それぞれの定義に従い Markdown／HTML の表で全行出力する。リンクサーバー設定とログインマッピングは別表にする。列見出しを添えたプレーンテキストやコードブロックだけでは掲載完了としない。保存後に全設定列・行数・値の一致を確認する。

## sysadmin・サービスアカウントの表示形式

[sysadmin 所属ログイン](sysadmin-logins.md#表形式での出力必須) と [サービスアカウントの DMV 結果](service-accounts.md#表形式での出力必須) は、各定義に従い列見出し付きの Markdown／HTML 表で全行掲載する。列の値・行数・件数を元結果と照合し、0件・取得失敗・未取得値を区別する。サービスの補助 ERRORLOG は別途コードブロック（HTML では pre）で本文全文を保持する。

## 構造化された結果の表形式

ログ本文を除く構造化された結果は、列見出し付きの Markdown／HTML 表で出力する。設定3項目は設定値・実効値・判定・根拠・注記、sa はログイン名・is_disabled・状態・判定・根拠、TRUSTWORTHY は集計と DB 一覧、DAC の2項目は [表形式ルール](dac-checks.md#表形式での出力必須) に従う。すべてのチェックの集計値は項目・値の表等で掲載し、証明書ログの分類別件数も表にする。既に表形式を指定している一覧も継続する。

0行でも列見出しと0件を明示し、取得不能は未判定と理由を記載する。Configuration option・サービス補助・証明書のログ本文は日時・プロセス・分類（該当時）を含めコードブロックで全行保持する。表にする際は、空白を含む名前・述語・サービス名・アカウントを単純な空白分割で壊さない。原文の再構成一致だけで列境界の正しさを保証せず、SQL の列定義と各値の意味も確認する。

## 生成と確認

- 同じ一括実行で取得した結果を使う。レポート作成だけのために再接続・再認証・再実行しない。過去の結果を使う場合は元の実行日時と今回の生成日時を分けて明記する。
- sqlcmd 出力は型付きデータではない。単純な空白分割で列やログを壊さず、折り返しや出力の切り詰めによって欠けた結果を捏造しない。完全な結果を取得できなかった場合は欠落範囲を明記し、完全なレポートと称さない。
- パスワード、トークン、MFA コード、接続文字列の秘密部分は保存しない。診断に必要なログイン名・DB 名等は対象として記載する。ログに秘密情報が含まれる場合は該当部分だけを伏せ、伏せ字にしたことを注記する。通常のログ本文や空白・改行は改変しない。
- 書き込み後にファイルを読み直し、UTF-8、全選択項目の目的説明、必須の構成、サマリーと詳細の整合、検出件数と掲載行数、未判定理由、秘密情報の混入がないことを確認する。保存失敗は診断の失敗と分けて報告し、保存できていないのに生成済みとしない。
- 最後にレポートの絶対パスへのクリック可能なリンクと、主要結果・未確認事項を簡潔に返す。全詳細はファイルに載せ、チャットでは要約してよい。

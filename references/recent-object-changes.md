# 直近7日間で変更されたオブジェクト

- 目的: 全データベースを対象に、最近のオブジェクト変更を情報として列挙する。変更の有無を正常／異常と判定しない。
- 一時オブジェクトの除外: 一時オブジェクトは対象外とする。tempdb で名前が # で始まるオブジェクト（ローカル・グローバル一時テーブル、一時プロシージャ、表変数等）と、parent_object_id がそのオブジェクトを指す子オブジェクト（制約等）を SQL で除外する。tempdb 全体や他 DB の恒久オブジェクトを除外しない。DB 別件数・サマリー・一覧はすべて除外後の値で一致させ、除外後0件の取得成功 DB は既存ルールに従って省略する。
- 対象: `sys.databases` に見える全 DB（システム DB を含む）の `sys.objects`。`is_ms_shipped = 0` のスキーマスコープのオブジェクトを対象とする。
- 期間: SQL Server のローカル日時 `SYSDATETIME()` を実行開始時に固定し、7日前以上・開始時刻以下の `modify_date` を抽出する。暦日ではなく直近7日間。新規作成も含む。
- SQL: [check-recent-object-changes.sql](../assets/queries/check-recent-object-changes.sql)。DB 名を QUOTENAME で引用し、期間はパラメーターで渡す。同じ接続内で DB を順に参照し、再認証しない。結果の保持はセッション内の表変数のみ。
- 必要権限: DB 一覧の可視性、各 DB への CONNECT、対象メタデータの参照権限。各 DB の VIEW DEFINITION の有無も取得する。権限の自動付与は行わない。
- 判定: 取得できた対象があれば「検出あり」、0 件なら「検出なし（可視範囲）」。VIEW DEFINITION を確認できなければ「未確認（部分取得）」とし、取得できた行は出力する。個別の DENY 等による非表示オブジェクトも未確認。
- 取得できない場合: オフライン、アクセス不可、SQL エラーは DB ごとに「未確認」と理由を出し、他の DB を継続する。非表示 DB は列挙できず未確認。DB が0件の場合やバッチ全体の失敗・タイムアウトは未判定とし、全 DB の確認完了とは報告しない。
- 出力: 対象期間（サーバーローカル時刻）、可視 DB 数、DB ごとの状態・件数・取得状況・理由、一時オブジェクトを除く検出した全オブジェクトの DB 名・スキーマ名・名前・種類・作成日時・変更日時。件数だけで済ませず全行を表で報告する。
- 限界: 定義の最終変更日時を確認するもので、データ行の更新や変更者・変更内容・削除済みオブジェクトは取得しない。DDL トリガー等のスキーマスコープ外のオブジェクトは対象外。テーブル／ビューの modify_date はインデックスの作成・変更でも更新される。実行中の変更を固定したスナップショットではない。
- 実行: 一括入口の既定項目に含む。単独では `-Checks 'recent object changes'`。設定・永続データは変更しない。

## 表形式での出力（必須）

チャットとレポートの両方で、DB ごとの取得状況と変更オブジェクト一覧を、列見出し付きの表にする。Markdown は Markdown テーブル、HTML は table 要素を使う。sqlcmd のプレーンテキストやコードブロックの貼り付けを表の代わりにしない。

- DB ごとの表: DB 名、状態、検出件数、取得状況・判定、未確認理由・注記。DB ごとの取得状況表では、取得成功かつ検出件数が0件の DB 行を省略する。1件以上の DB と、取得失敗・未確認（部分取得を含む）の DB は件数にかかわらず掲載する。全 DB のチェックは継続し、対象 DB 数・掲載 DB 数・0件で省略した DB 数を明記する。全 DB が取得成功で0件なら個別 DB 行は掲載せず「検出なし（0件）」と省略 DB 数を示す。変更オブジェクトの行は省略しない。
- オブジェクトの表: DB 名、スキーマ名、オブジェクト名、種類、作成日時、変更日時。1オブジェクトにつき1行とし、全対象行を掲載する。DB 別に表を分割してよいが、件数上限や省略記号で行を省かない。
- 対象期間・可視 DB 数・判定根拠は表の前後に記載する。0件は「検出なし（0件）」、未取得は件数を不明として未判定と理由を記載し、架空のオブジェクト行を作らない。
- 名称内の空白・区切り文字・改行を保持できるようエスケープする。曖昧な sqlcmd 出力を単純な空白分割で列へ割り当てない。列を確定できない行は推測せず、表に未判定の理由を記載する。
- 表の行数を DB ごとの検出件数と照合し、全行掲載と値の一致を確認する。元の出力を補足資料として保持しても、本文の表は必須。

# ERRORLOG による暗号化接続用証明書の確認

- 目的: SQL Server の暗号化接続用証明書に関するログを確認し、読み込み成功・自動生成証明書・読み込み失敗を区別する。
- 対象と SQL: [check-encryption-certificate-log.sql](../assets/queries/check-encryption-certificate-log.sql)。`sp_readerrorlog 0, 1, N'certificate'` で現在の Database Engine ERRORLOG を検索する。選択名は `encryption certificate log`、既定の一括チェックに含める。
- 必要権限: sp_readerrorlog の実行・ログ参照権限。実環境の権限で取得し、権限不足は未判定とする。権限の自動付与、バージョン下限による実行禁止は行わない。
- 分類: 英語メッセージの内容から「証明書の読み込み成功」「自動生成証明書の読み込み成功」「証明書の読み込み・暗号化初期化失敗」「その他の証明書関連ログ（内容確認）」を付ける。SQL Server のイベント 26013、26018、26010／26014／26015／26017 に相当する代表的なメッセージを扱う。番号だけから本文を推測しない。未知のメッセージや別用途の証明書ログも捨てず、その他として出力する。
- 判定: 検出時は「情報（検出ログ参照）」とし、分類別の件数・本文を報告する。0件は「未判定（該当ログなし）」、読み取り失敗は理由付きの「未判定」。成功と失敗が両方あれば全行と日時を併記し、最新の1行だけで現在の状態を断定しない。
- 出力: ログ番号、検出件数、分類別件数、全行の日時・プロセス・分類・本文全文。ハッシュが本文に含まれる場合はそのまま記載し、ハッシュのないメッセージから証明書を推測しない。本文の Cert Hash(sha1) は識別用の拇印であり、証明書の署名アルゴリズムと同一視しない。
- 範囲の限界: 現在のログだけを読む。ログの切り替え・保存期間・言語によって起動時の行が見つからない場合がある。過去ログ、英語 certificate を含まないメッセージ、証明書に言及しない TLS／セキュリティライブラリのエラーは未確認。過去ログの追加検索は指示された範囲で行う。
- 安全性の判定はしない: 読み込み成功は有効期限・CN/SAN・信頼チェーン・失効・暗号強度・クライアント側検証の成功を保証しない。ハッシュ付きの成功メッセージだけで CA 発行証明書と判断しない。自動生成証明書の使用も独自に正常／異常判定しない。Force Encryption や現在の全接続の暗号化状況は対象外。
- 操作の境界: 同じ通常接続でログを読み、証明書ストアの参照・変更、証明書の取得／登録／更新、サービス再起動、接続テスト、ログのローテーションを行わない。既存の `-N -C` は維持し、このチェックで証明書検証を実施したとは報告しない。

## 結果報告のひな形

- 実行状況／接続先／実行日時／対象ログ番号:
- 判定／検出件数／分類別件数:
- 全ログ行: 日時・プロセス・分類と本文全文をコードブロックに掲載。
- 未確認事項: 過去ログ、未知のメッセージ、証明書の現在の有効性・信頼性、暗号化設定等。
- 設定・証明書変更: なし。

# チェック定義テンプレート

ユーザーから実装内容の指示を受けた段階で、このひな形を別の定義ファイルにコピーして記入する。
具体的なチェック項目・判定基準はユーザーの指示に従い、テンプレートの空欄から推測しない。

## チェック定義のひな形

| 記入欄 | 内容 |
| --- | --- |
| 項目名 | [未記入] |
| 目的 | [未記入：何を把握し、なぜ確認するのか。確認できる範囲と限界] |
| 対象 | [未記入：対象範囲と適用条件] |
| 必要権限 | [未記入：情報取得に必要な権限] |
| 使用する SQL | [未記入：完成した SQL ファイルへの参照] |
| 判定基準 | [未記入：取得値と判定の対応、判定に必要な根拠] |
| レポート掲載内容 | [未記入：選択時のサマリー・詳細節、全結果セットの列、0件・失敗時の表示方法] |
| 取得できない場合の扱い | [未記入：取得不足の識別方法と報告内容] |

定義と SQL が完成するまでは実行対象に含めない。
判定基準の未記入、SQL の未実装・未実行、権限不足やエラーによる取得不能は「未判定」とし、理由を記録する。
空の結果や一部の取得値だけで「正常」と判断せず、定義した判定に必要な根拠が揃っているかを確認する。

## 結果報告のひな形

**チェックの目的**:

[未記入：実施理由を説明。取得結果・判定根拠とは区別する。句点ごとに表示上も改行する]

- 対象サーバー／データベース: [未記入]
- 実行状況（未実行・プレビューのみ・実行済み）: [未記入]
- 実行日時: [未記入：未実行の場合はその旨を記載]
- チェック定義／使用した SQL: [未記入]

| 項目 | 取得値 | 判定 | 根拠 | 未確認事項 |
| --- | --- | --- | --- | --- |
| [未記入] | [未取得] | 未判定 | [適用した判定基準と取得結果。根拠不足の場合はその理由] | [未確認の範囲と理由] |

プレビューや接続確認の成功を、セキュリティチェックの実行成功・正常判定として報告しない。
報告には必要な取得値だけを記載し、秘密情報を転記しない。

スキル実行後は、この項目別の報告を [レポート出力手順](report-output.md) に従ってファイルにまとめる。サマリーに加え、各定義で指定された全対象行・未確認理由・設定変更の有無を記載する。

新規項目は [レポート掲載表](report-output.md#全チェックの掲載義務) に登録する。選択された項目は0件・取得不能・未実行でもサマリーと詳細節から省略しない。レポートへの反映と照合までを追加作業に含める。
